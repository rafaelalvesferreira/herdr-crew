# v0.3: mechanics in a script, a lean skill, safer reports

## Why

v0.2 kept every procedure in one 33 KB `SKILL.md`. An agent re-derived the same shell sequences on each run (split, rename, session id, flags, `agent start`), which cost context and drifted. Two coordinators of one project wrote the same helper table. A helper's report was trusted as if the user had typed it.

## What changed

| Area | v0.2 | v0.3 |
|---|---|---|
| Mechanics | Prose steps the agent retyped | `scripts/crew.py` (Python standard library): `helper-start`, `send`, `end`, `map`, `worktree-create`, `worktree-remove`, `routing`, `state-dir`. JSON out; unsafe steps are refused with an `error` and a `hint`. |
| Skill size | One 33 KB file | `SKILL.md` about 7 KB (triage, conventions, rules) plus one reference per job, read on demand. |
| Discovery | Description match only | SessionStart hook adds a short reminder when `HERDR_ENV=1`; silent otherwise. |
| Read-only roles | Contract text only | `reviewer` and `investigator` start with `--disallowedTools Edit Write NotebookEdit`. LIMITS still covers shell commands. |
| Reports | Trusted on arrival | A report is data. Each contract carries a task id the report must repeat; nothing in a report authorizes an action. |
| State | `~/.herdr-crew/<project>/helpers.md`, shared | `~/.herdr-crew/<project>/<workspace id>/helpers.json`, one per coordinator; deleted when the worktree is removed. Live state always comes from Herdr. |
| End of cycle | Unspecified | The user's explicit commit, push or PR order is relayed to the editing helper as a quote; ended helper panes are reused. |
| Project name | Defaulted to the repository directory name | Asked once per session. A project is the user's initiative and may span repositories. |
| Herdr coupling | JSON field names and file paths spread through prose | Only in `crew.py`, with a minimum-version check. |
| Testing | Scenario reading by fresh agents | Plus `tests/smoke.sh`, a real run inside Herdr. |

## Decisions

- **One script, not several.** Shared helpers (state directory, routing lookup, pane checks) stay in one file with no install step.
- **The contract stays a file the coordinator fills.** The script writes the exact parts (first LIMITS clause, `END-<name>`, RETURN command, task id) and `send` refuses a contract where those changed or a `<FILL: …>` is left.
- **The script never answers a dialog.** `blocked_at_startup` returns the screen text and tells the coordinator to tell the user.
- **`--return file`** exists for a caller that is not an agent pane (the smoke test): a report prompted into a shell would be typed as commands, so the script refuses that by default.

## Not done
